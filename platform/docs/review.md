# 平台设计文档复核

历史记录说明：本页保留实现前的设计复核结论。此后应用、部署与联网开发固件已交付；当前状态及实际CI结果见[交付状态](delivery.md)和[软件验收记录](../reports/README.md)。下文“待开发/未实测”描述的是设计复核时点，不是当前源码状态。

复核日期：2026-11-04。对象为本目录的MVP架构、数据模型、设备协议、开发/部署计划、固件接入说明、JSON Schema与两份合成样例。**这是文档与契约一致性复核，不是Django服务、数据库、联网固件、性能或实机测试报告。**

## 复核结论

文档围绕一个机构、一个单体应用、一个数据库、两个业务页面展开；现有Django能力承担账号与基础资料管理。设备只上传最近快照，没有在首版增加消息代理、后台任务队列、远程控制或医疗报警。当前设计可作为下一轮最小实现依据；应用与设备接入仍待开发。

| 检查范围 | 最终约定 |
|---|---|
| 现有固件与拟实施能力 | V0.2.0只有本地UART/USB日志；Wi-Fi、TLS、UTC、设备身份和启动计数均明确列为待开发，不把串口输出当成已有平台接口 |
| 设备重启与乱序 | `boot_id`统一为设备持久递增uint32；提交成功后才联网；服务器保留启动、序号、uptime与采集时间水位，旧包不覆盖最新状态 |
| 床位与住户归属 | 明确上传不可变`binding_id`，不靠有偏差的时钟猜住户；换绑轮换凭证、清空最新显示、保留防回退水位，现场重新配置并重启 |
| 并发与撤销 | 写入和管理动作共享Device行锁；锁内再次确认凭证、启用状态和绑定；数据库活动绑定唯一约束兜底，不仅依赖Admin表单 |
| 有效性与状态 | 采集时5秒质量窗口、页面30秒最近观测时效与60秒无新上报分开；unknown不显示为离床，无效体征不填0或沿用旧值 |
| 趋势与缺口 | 同时显示上报完整度和收到点的有效比例；不把10秒快照交给2秒积分口径，不推算睡眠时长或真实离床次数 |
| 时间窗口 | 趋势/导出起止对齐UTC整分钟，最多24小时、1440分钟桶；边界按绑定期间与隔离期裁剪，缺失不插值 |
| 权限和数据处理 | 查看员只读，CSV仅管理员；设备凭证只有本机写权限；日志/审计不复制token或完整健康载荷，导出文本处理公式前缀 |
| 实施与运维 | 100台容量、P95、恢复时限与3台真机试点均标为未来验收目标；保留与备份期限不冒充立即删除所有副本 |

复核期间已修正：随机boot UUID无法严格排序的问题、换绑时旧数据归属和latest残留风险、事务外鉴权的撤销竞态、未启用样例的质量原因、任意秒窗口与1440桶上限冲突，以及“换绑现场停测”与“平台停用”的不同含义。P0未上传ambient，因此平台不声称显示光照确认状态。

## 未被本轮验证的事项

- 尚无运行中的服务、数据库迁移、页面、部署容器或设备联网固件；不能把文档检查写成这些功能已经通过测试。
- JSON结构校验不能验证授权、数据库唯一性、事务并发、真实时间、设备启动计数可靠性或物理安装；这些必须在下一轮实施后按[开发验收](development.md)逐项执行。
- 真实设备仍须现场确认供电与安装。绑定只记录归属，不识别住户或分离多人；同房/邻床多设备场景须实际验证。
- 100台设备和10个浏览会话只是规划目标；数据行大小、主机容量、TLS内存、网络故障下采集与灯控响应、备份恢复均尚未实测。

本地链接、Schema与样例的[自动检查](validation.json)共36个正反例通过，包含文档内JSON同步检查、显式UTC日期格式检查及非法boot计数拒绝。可用[校验脚本](../tools/validate_contract.py)复现；其通过范围仅限文档产物，不覆盖尚未实现的服务端语义。
