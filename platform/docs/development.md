# 开发计划与验收

本页保留2026-11-04的开发顺序与验收基线。Django应用、迁移、页面和部署材料已按阶段落地，最新交付状态见[平台入口](../README.md)，运行步骤见[运行与恢复](operations.md)。联网固件、真机与完整容量验收仍未完成。每一阶段先完成可演示闭环，不预先做扩展平台。

## 1. 建议源码布局

```text
platform/
  README.md
  docs/                       # 当前设计文档
  contracts/telemetry.schema.json
  examples/                   # 当前合成协议样例
  app/                        # Django单体实现
    manage.py
    config/                   # settings、urls、WSGI
    monitoring/
      models.py
      services/               # ingestion、bindings、queries
      views/                  # device、pages
      admin.py
      templates/monitoring/
      static/monitoring/      # 本地CSS与原生JS
      management/commands/
      tests/
  deploy/                     # Dockerfile/Compose/Nginx与备份恢复脚本
```

仅一个业务Django app；先用内置User，角色用Group/Permission，不为未来猜测自定义用户域。schema及样例是协议文档产物，不等于服务端校验代码已经实现。

## 2. 四个实施阶段

| 阶段 | 要做的工作 | 完成标准 |
|---|---|---|
| M1 数据接入 | 初始化单体/迁移；设备登记与凭证；完成接入契约、绑定事务、模拟器 | 3台合成设备能各写各的数据；重复/乱序/身份/质量/绑定错误测试通过；没有设备也可验证 |
| M2 管理闭环 | 两角色、Admin动作、总览、绑定详情、曲线、缺口、受限CSV与审计 | 一床一机、换人后历史分开；旧值过期；查看员不能写或导出；10会话演示 |
| M3 真机接入 | 固件快照与USB解耦、Wi-Fi/TLS/SNTP、持久boot计数、token与绑定配置、独立网络任务 | 3台真机持续24小时受控试点，断网/重启/换床测试；记录真实失败与资源，不混作模拟结果 |
| M4 部署交付 | 三容器、权限与网络限制、日清理、加密备份和恢复演练；100台模拟压测 | 完成下表容量/恢复验收；生成实际部署文档与锁文件，再由机构安排有人值守试点 |

不先建设报警通知、远程控制或复杂日报。即使M4通过，PCB V0.2的人工作业上电限制仍保留；无人值守恢复另立硬件/固件验证项。

## 3. 开发规则

- 服务端先实现`ingest_telemetry`与`replace_binding`，再写页面；同一规则不在Admin、API、UI各自复制。
- JSON Schema Draft 2020-12要启用`format`校验，日期还需严格UTC解析；仅校验`Z`后缀不够。重复JSON键和非有限数要在解析阶段拒绝。数据库与跨字段规则仍由服务函数检查。
- 事务和并发测试使用PostgreSQL，不用SQLite测试结果代替条件唯一约束、行锁、JSON和时间行为。
- 模拟器使用登记为`is_simulator=true`的设备与专用演示部署；页面与导出必须标记“模拟”。生产设备不自行声明或切换这个标记。示例ID、版本和时间均为占位，工具应生成当前时间，不拿旧日期循环冒充实时。
- 固件保留V0.2发布包；联网改造使用新的开发版本，单独记录构建、模拟与实机结果。Flash配置失败不使计数归零后继续联网。
- 所有表单/HTML输出使用模板自动转义；HTML片段刷新失败保留错误状态并使旧数据过期，不能静默保持“在线”。

## 4. 必测行为

| 测试组 | 必须得到的结果 |
|---|---|
| 格式 | 额外字段、重复键、字符串布尔、非法UUID/日期、计数溢出、NaN/Infinity、超4KiB被拒绝 |
| 身份 | 无token/错token失败；A的token写B失败；设备token不能读页面；停用/轮换后即使并发在途也不能按旧授权入库 |
| 幂等与顺序 | 同键同体仅1条且不续新鲜时间；同键异体409；旧seq/旧boot不覆盖latest；新boot计数更高可重置seq；时钟反跳拒收至恢复 |
| NVS启动计数 | 原子写成功后才上传；写失败/键损坏/既有身份但计数丢失时停止上传；断电跳号可接受；出厂重置重新登记身份 |
| 测量 | 安装未确认、传输故障、活动、无效0/255、越量程均不可显示为有效体征；unknown不变成非在床 |
| 状态边界 | 在接收/采集年龄30秒两侧及接收年龄60秒两侧检查；重复包不能让断采设备保持新鲜；浏览器断连后也自动标过期 |
| 绑定并发 | 两管理员同时占同床或同机，只有一个成功；历史别名/位置不被改写；换绑清空latest，保留防回退水位；旧token/旧binding被拒绝 |
| 隔离期 | 新绑定前5秒不接收；两端null只进工程诊断；换人后延迟旧包不能进入新绑定 |
| 统计 | 零分母null；一段有10%上报且收到点全有效时显示完整度10%和有效点100%；缺失分钟断线，不把有效点比例叫整夜时长 |
| 权限与导出 | 查看员对Admin与CSV均403；越窗/无限查询失败；公式前缀文本被转义；审计/日志不含token或完整健康载荷 |
| 网络故障 | TLS错误无明文降级；慢TLS/服务器超时不阻塞UART/灯；无无限重试队列；断网后只传新数据 |
| 重启现场流程 | 网络恢复后仍可能待雷达启用/安装确认；不远程恢复现场确认，按键与灯保持原有行为 |
| 多设备现场 | 同房/邻床同时运行，覆盖邻床活动与不同安装角度；确认每台观测对应目标床位。绑定不提供住户识别或多人分离，串床时先修正安装/适用场景 |
| 数据维护 | 7天历史删除后latest外键安全；过期住户代号清理；备份恢复后账号、绑定和水位一致 |

## 5. 性能与试点门槛

以下均为**验收目标，尚未执行**。以4 vCPU/8 GiB/100 GiB SSD候选主机为基线，记录实际机器、软件锁版本、请求量、数据库增长与P95延迟。

- 100个模拟设备每10秒一包，10个浏览器每15秒刷新，至少24小时；请求错峰并另外测100台同时重连的突发。
- 正常网络下接入服务端P95处理时间≤500 ms、总览接口P95≤1秒；这些是服务器目标，不含无线与互联网传输时间。
- 在同机产生预期7天规模约605万行的合成数据后，单绑定24小时趋势/CSV查询P95≤2秒；同时保持正常接入。不同物理表行大小须实测。
- 正常输入不出现500错误，不接受跨设备或跨绑定写入；应用重启后水位与幂等保持。丢包率、收到/应有时隙数和拒绝原因必须能解释，不用平均值掩盖断连。
- 3台真实硬件24小时中记录堆内存峰值、UART错误、有效点比例、网络重连、按键/灯响应；不得把100台模拟容量写成100台实机验证。
- 从备份恢复到空库，目标RTO≤2小时；每日备份的计划RPO≤24小时，须记录演练结果，不能只检查压缩包存在。

如果不达标，先定位索引、查询、payload大小或网络任务，不先上微服务/消息队列。开发交付应附自动化结果、实机记录和仍未通过事项；本轮的[文档复核](review.md)只验证设计文件一致性。
