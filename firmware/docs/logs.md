# 离线日志与工程摘要

`src/main.cpp` 约每秒输出一条 schema 1 JSONL 状态快照。日志输出可能延迟，原始传感器字段也可能是缓存值，不能将每秒输出一行解释为每秒取得一条新的雷达读数。本文与摘要工具只说明工程观察统计，不连接硬件，不推断临床睡眠、医学事件、医学报警或真实离床次数。

## 使用

在项目根目录执行，Python 3 无需额外依赖：

```sh
python3 firmware/tools/summarize_log.py firmware/fixtures/demo_synthetic.jsonl \
  --json firmware/reports/demo_summary.json \
  --markdown firmware/reports/demo_summary.md

python3 -m unittest discover -s firmware/tests -p test_log_summary.py -v
```

输入、JSON 输出与 Markdown 输出路径必须各不相同。工具创建缺失的输出目录，覆盖指定的已有输出文件，不改写输入。输入为空或全部不合格时仍输出摘要，覆盖率与中位数为 `null`，不会把没有数据解释为 0% 或零读数。

`demo_synthetic.jsonl` 及 `demo_summary.*` **均为合成模拟非实测**。示例首行含 `{"schema":1,"type":"meta","synthetic":true}`，工具会自动醒目标注。其他合成输入也可使用 `--synthetic` 标注。没有标志不等于本工具已证明来源为实测。

## 字段和有效性

处理的记录须为 `schema=1`、`type=sample` 对象，含非负 uint64 `t_ms`，以及 `presence`、`bed`、`rr`、`hr` 四个对象。每个对象必须具有布尔 `available`、`valid`、整数 `raw` 和 uint32 `age_ms`。占用字段原值为 0 或 1，RR/HR 原值按固件的 uint16 范围检查。`available=true` 时，`age_ms` 不得大于 `t_ms`；`valid=true` 必须同时 `available=true`。

质量判断沿用日志的 `valid` 标志，工具不重算或替换固件的量程、安装确认、传输、运动和新鲜度规则。`ready`、`vendor_stage`、`trend` 等其他字段不参与本文统计。只有 presence 与 bed 均有效且二者为 1，才记为在床观察；两者均有效的其他一致组合记为非在床；任一无效或 presence=0、bed=1 的冲突组合记为 `unknown`。

RR/HR 的 available 原始分布保留日志中已获得但可能无效的原值；Markdown 表格使用 valid 原始分布。两者都在 JSON 中保留计数、最小值、最大值、中位数。0、255 等无效读数是否被固件判为无效，以日志标志为准；这些数值不解释为呼吸停止等事件。

## 时间规则

按源文件顺序处理，不排序。`t_ms` 是一次开机内的 64 位相对毫秒数，不是日期时间，不能用 32 位 `clock_ms` 替代。每次 `t_ms` 下降都开始新段，报告“重启或乱序边界”；只有日志不能分辨实际重启与乱序。每段单独保留起止来源行和时间范围，不估算跨段时长。

计时间必须同时满足以下条件：

1. 前后为同段相邻结构合格的 sample，中间没有坏行或非 sample 记录。
2. 时间差大于 0 且不超过 2000 毫秒。
3. 左端不是重复时间记录。

每个计入区间用左端记录的占用状态与 RR/HR 有效标志计数。恰好 2 秒可计入，超过 2 秒的整个间隔排除，不截取头两秒、不插值补齐。末条记录没有右端，不贡献时长。空白行忽略；坏 JSON、不合格 schema、错误事件和其他非 sample 记录阻断时间连续性。

相邻重复时间单独计数，零长度区间不计时，其后一个区间也保守排除，避免用重复时间行覆盖原状态。重复行的 RR/HR 可见原值仍参加观测键去重，冲突会在 JSON 中暴露。时间回退另计下降次数并切段；每段第一条可作为该段后续区间的左端。

报告同时列出：

- **各段首末跨度之和**：各段最后 `t_ms` 减最初 `t_ms` 后相加，不包括跨段空白。
- **可积分观察时间 observed_ms**：满足上述规则的区间之和。
- **未计正向间隔 excluded_forward_ms**：同段可比较的正向区间中，被缺口、坏行或重复左端排除的时长。
- **在床、非在床和 unknown**：仅在可积分观察时间内三者互斥相加；缺口不补进 unknown。
- **RR、HR 与两者同时有效覆盖**：相应左端有效区间之和，分母是可积分观察时间；另列可积分时间占各段跨度之和的比例。

因乱序而分出的不同段可能覆盖相同真实时间；各段相加只是按日志顺序独立核算，不能据此宣称实际整夜时长。没有绝对时钟也不能定位真实日期或跨重启的空白。unknown 不表示无人或离床；在床不表示睡着。

## 原始读数去重与追溯

RR 与 HR 分别以 `(segment_id, t_ms - age_ms)` 作为观测键，同一缓存读数出现多行只计一次。不得共用 RR 与 HR 的去重时间，也不以 `raw` 相等去重；不同观测时刻的相同原值仍为不同可见观测。同键在任一来源行标为有效，可进入 valid 原始分布；同键出现不同原值时记冲突，从 available 和 valid 两种分布都排除，避免任意选择一个值。

中位数来自去重后的原始 `rr.raw` / `hr.raw`，不使用固件的趋势中位数再求中位数，也不按持续时间加权。末条记录可以提供一条可见原始观测，但没有后续时间证据，所以不会贡献时间覆盖。同毫秒的多帧可能被同一个观测键合并，日志之间未显现的雷达更新也无法恢复；去重计数不是雷达全部采样数或 UART 总帧数。

JSON 保存源路径、字节数、SHA-256、固件版本、异常来源行、各段范围、每个正向区间的左右来源行及计入/排除原因，以及每个观测键的原值和来源行。借助相同输入文件与哈希可复核统计。标准之外的 NaN/Infinity 数值和重复 JSON 属性按无效 JSON 排除，字符串布尔值不会自动转成真值。

## 模拟示例预期

模拟输入包含 13 条结构合格 sample、一条 synthetic 元数据、一条坏 JSON、一处重复时间、一处时间下降和一个 4 秒缺口。预期结果为 2 段、14 秒段跨度、8 秒可积分观察、6 秒未计正向间隔；其中在床观察 6 秒、unknown 2 秒，RR/HR 有效时间均 6 秒，占可积分观察时间 75%。RR 去重有效原始中位数 17 次/分钟，HR 为 71 次/分钟，各有 6 个有效观测键。以上数字仅验证统计规则，**不构成设备实测性能或临床结果**。
