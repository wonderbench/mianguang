# 睡眠趋势与夜灯业务逻辑

`sleep_core` 是与串口、Arduino 和硬件驱动无关的 C++17 模块。首版只形成有效呼吸/心率趋势，并保留模块原始睡眠阶段估计，不推导临床睡眠分期、不诊断疾病、不发出疾病报警。测试验证的是软件逻辑，不是 C1001 的实测性能或医学有效性。

## 接入顺序

1. 驱动将每个已接受字段写入 `SensorSnapshot`，同时更新该字段的 `updated_ms` 和 `available`。没有收到的字段保留原时间戳，不能因为收到其他报文而整体刷新。时钟使用与主循环相同的 `uint32_t` 毫秒时钟。
2. 默认 `installation_confirmed=false`、`transport_ok=false`。安装位置、朝向及实际在床覆盖确认后才设置安装确认；已接受的传感器输入可恢复 `transport_ok=true`。已知协议或串口故障应立即设为 `false`，不能把未知状态写成无人或离床。
3. 每轮调用 `evaluate(snapshot, now, QualityConfig{})`。其结果只适用于该快照和该次评估时刻，不能缓存为永久有效。
4. 每轮调用 `TrendWindow::update(snapshot, quality, now)`，即使没有新数据也要调用，以便老数据退出窗口。`summary()` 只读取当前统计，不推进时钟。
5. 调用 `makeNightInputs(snapshot, quality, dark_known, dark)`，将结果交给 `NightLight::update(now, inputs)`。返回值是 0～255 的逻辑亮度，由硬件层映射为 PWM。
6. 短按/长按在硬件层完成去抖与分类后，分别调用 `shortPress(now)`、`longPress(now)`。切回自动时调用 `setAuto(now)`。业务模块不读取 GPIO。

## 数据质量与趋势口径

所有字段都带独立的新鲜度。默认阈值为 5000 ms，可通过 `QualityConfig.freshness_ms` 配置；这是待整机联调验证的工程默认值，不是 C1001 的实测报告周期。恰好等于阈值仍算新鲜。

呼吸有效量程为 10～25 次/分钟，心率为 60～100 次/分钟，端点包含在内。这些是首版采用的模块标称范围，不是人体正常值或疾病判断阈值。有效读数还要求安装已确认、传输状态正常、presence 与 in_bed 两项都新鲜且为真、低体动状态新鲜且为真。零、255、缺失、过期、体动及越量程均不进入统计；零或缺失不解释为呼吸停止。

`FieldQuality` 提供 `valid` 和 `QualityError`。已知传输故障会使全部字段失效。其他情况下依次检查字段缺失、安装确认和新鲜度；生命体征再检查无效标记、量程和测量条件。一个字段只返回首个失败原因。presence 为假而 in_bed 为真属于冲突状态，不能用于夜灯。有效的离床状态不需要低体动，低体动门控只用于生命体征和模块阶段估计。

`module_sleep_stage` 保存厂商字段原码，并使用上述测量条件校验。仅接受已知枚举 0～3，其中 3 表示厂商的 none（非睡眠），不能展示成睡眠阶段；大于 3 的未知枚举（包括 255）一律返回 `InvalidValue`。0～2 的显示名称由已核验的协议定义提供。本模块没有自定义阶段算法，也不会把一个整数重新命名为医学分期。

趋势窗固定为 60 个 1 秒桶，桶边界由首次 `update` 的时刻建立。每个指标在一个桶中最多接纳一个有效观测，取该桶第一条有效数据，并要求字段时间戳属于当前桶。被原桶丢弃的后续报文不能靠下一次读取缓存进入新桶；同一字段时间戳不会跨桶重复计入，比已接纳观测更旧的回放也会被拒绝。协议层应按时间顺序提供最新快照，不回放历史数据；时间戳是观测标识，同一毫秒内的多个观测合并看待。字段的去重历史随统计窗口过期，持续运行但超过 24.8 天没有有效测量后，新的有效观测仍可立即恢复统计。呼吸与心率分别计算有效桶数、中位数和覆盖率。偶数样本中位数取中间两项均值。

覆盖率固定为“有效桶数 ÷ 60”，统计当前正在进行的桶与前 59 个桶，包括启动阶段尚未积累的桶。例如刚启动只有 1 个有效桶，覆盖率为 1/60；若从 0 ms 起每秒都有数据，在 59000 ms 可首次达到 60/60。这是“60 个采样桶的观测覆盖率”，不是精确最近 60 秒的连续有效时长比例。桶按整秒边界整体退出，边界内不会逐毫秒淘汰。若当前桶起点为 B，则所含桶起点为 B−59000 至 B；当前实际已观察的范围截至 now，B 至 B+1000 尚未结束。

空窗 `available=false`，`median=0` 仅为数值占位，界面必须按 `available` 显示“暂无有效数据”，不能显示为真实零值。数据过期会禁止新样本入窗；过去有效的历史桶仍保留至滚动窗口自然退出。此统计也不表示整夜睡眠时长或整夜数据有效率。

## 夜灯行为

启动为自动模式且熄灭。必须先观察到有效在床，再观察到连续 3000 ms 的有效离床，才能尝试自动开灯。离床证据时间使用 presence 与 in_bed 中较旧的更新时间，并要求在确认点已经覆盖这 3000 ms。因此单条离床缓存数据即使仍在 5000 ms 新鲜期内，也不能因反复读取而开灯。调用方必须持续更新两项状态；仅有状态变化事件、没有周期状态反馈时，需由协议层读取或查询真实状态，不能伪造更新时间。

任何未知、过期或故障状态都会中断离床计时。恢复有效离床后重新计时。出现明确在床则取消离床计时并重新允许下一次事件。占用状态还按观测时间排序：旧时间戳和同一时间戳的矛盾状态不能改变在床状态或重新允许事件，并会打断待确认离床。主循环应持续调用 `update`；模块只能评价实际提供的观测，不能证明未观测间隔内的物理状态。

确认离床时只有 `dark_known && dark` 才开灯。环境明亮或明暗未知都会消耗本次离床事件，不会在后来变暗时补触发；必须重新有效在床后才允许下一次事件。默认没有环境感知就保持 `dark_known=false`，不能猜测为夜间。

默认亮度档为 32、96、192，初始选择 96；默认从当前亮度到目标亮度线性渐变 1000 ms。自动事件从触发时刻计时 60000 ms，随后用 1000 ms 渐灭。也就是说 60 秒包含最初 1 秒渐亮，完全熄灭约在触发后 61 秒。返回在床只重新准备下一次事件，不提前关闭本次定时灯；若在灯亮期间再次完成有效离床，新事件可重新开始 60 秒计时。渐变、亮度和延时可通过 `NightLightConfig` 调整。

短按切到手动并开关灯；长按切到手动并循环亮度档，原来熄灭时只改所选档位、仍保持熄灭。手动模式不受离床、环境亮度和自动超时干预，直到显式切回自动。切回自动会渐灭并清除旧的离床过程，要求重新观察有效在床。

所有相对时长采用无符号差值处理 `uint32_t` 计时回绕。配置间隔限制在 2^31 ms 以下；不能将持续 24.8 天以上未调用的状态或多个计时周期的历史时间戳当作当前观察。持续调用但长期缺少有效测量的场景已单独处理：趋势去重历史按窗口过期，夜灯在旧的占用排序基准超过可比较时域时清除此基准。建议主循环按正常交互频率调用，串口故障也继续运行质量、窗口与灯光更新。

## 本机断言与回放测试

标准入口只依赖 Python 标准库和 `clang++`，可从任意工作目录运行。脚本自动为 `tests/test_*.cpp` 中每个测试链接 `lib/sleep_core/src/*.cpp`，启用 C++17、严格警告、AddressSanitizer 和 UndefinedBehaviorSanitizer；编译、断言、运行、超时或检查器失败均返回非零值。默认临时产物在运行结束后清理，可用 `--build-dir` 指定保留目录。

```sh
python3 firmware/tools/run_native_tests.py
```

仅检查业务模块时也可直接编译：

```sh
c++ -std=c++17 -Wall -Wextra -Werror -pedantic \
  -Ifirmware/lib/sleep_core/include \
  firmware/lib/sleep_core/src/monitor_logic.cpp \
  firmware/tests/test_monitor.cpp \
  -o /tmp/test_monitor
/tmp/test_monitor
```

测试覆盖正常离床、启动离床不触发、明暗未知/明亮门控、故障打断、缓存离床报文不触发、再次在床后重新允许事件、手动优先、渐亮渐灭、迟到主循环补算超时、计时回绕、字段独立过期、体动门控、标称量程边界、零与255、窗口中位数/覆盖率以及同桶和同报文去重。

`test_replay.cpp` 提供确定性的业务适配层回放：启动缺失、8 小时整夜（含体动、无效生命体征、30 分钟故障、暗/亮/未知环境离床）、20 分钟手动优先、旧在床报文不得重新允许开灯、缓存测量不得跨桶、非整秒启动的桶淘汰边界、25 天故障后恢复、50 天稀疏运行以及跨 2^32 ms 的离床与渐变。回放使用 64 位逻辑时钟驱动真实 32 位接口，不使用真实等待，结果可重复。它验证业务链“快照→质量→趋势→夜灯”，不证明串口、硬件、C1001实测性能或医学有效性。
